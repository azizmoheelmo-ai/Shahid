# شاهد على الأداء الوظيفي

تطبيق ويب (صفحة واحدة) لمتابعة الأداء الوظيفي للمعلم، يشمل:

- تسجيل الدخول وإدارة الحساب (Supabase Auth)
- خطة الأداء الوظيفي، الأهداف، والتقييم الذاتي
- تسجيل "الشواهد" (الأدلة) وتصديرها كـ PDF / Word ومشاركتها عبر واتساب
- إدارة الصف (طلاب، شعب، سجلات سلوكية) والمتابعة الأكاديمية وخطابات الإحالة
- لوحة تحكم للمشرف/الأدمن (إحصائيات، صلاحيات، سجل تدقيق)
- نسخ احتياطي وتصدير شامل للبيانات (Excel / CSV / PDF / ZIP)
- موصل ذكاء اصطناعي (MCP، قراءة فقط) — يتيح لكل معلم ربط حسابه بمساعده الذكي الشخصي عبر رمز وصول خاص به

## التقنيات

- HTML / CSS / JavaScript (بدون إطار عمل) للواجهة
- [Supabase](https://supabase.com) كخدمة خلفية (مصادقة، قاعدة بيانات، تخزين ملفات)
- دالة خادمية واحدة على Vercel (`api/mcp.js`، Node.js) لموصل الذكاء الاصطناعي فقط — الواجهة نفسها تبقى صفحة ثابتة بلا خادم

## نموذج الفروع (Git) والنشر

- **`main`** هو فرع الإنتاج الحقيقي — أي دفع (push) إليه ينشئ نشرة Production فعلية يراها المستخدمون الحقيقيون مباشرة.
- أي فرع تطويري آخر (مثل فروع العمل النشطة) ينشر تلقائيًا كـ**Preview** منفصل فقط، بلا أي أثر على الإنتاج، حتى يُدمج بـ`main` بقرار صريح.
- هذا مُهيَّأ بإعدادات Vercel (Project Settings → Environments → Production → Branch Tracking).

## ملفات المشروع (لازم تترفع كلها مع بعض عند الاستضافة، بنفس بنية المجلدات)

| الملف/المجلد | الغرض |
|---|---|
| `index.html` | الصفحة الرئيسية (HTML فقط + وسوم تحميل الملفات التالية) |
| `style.css` | التصميم |
| `app/app-01-core.js` … `app/app-09-shahid-form.js` | منطق التطبيق (JavaScript)، مقسَّم لـ 9 ملفات حسب الوظيفة — **يجب أن يبقى مجلد `app/` كاملاً بنفس أسماء الملفات**، لأن `index.html` يحمّلها بالترتيب عبر `<script src="app/...">` |
| `sw.js` | Service Worker (تخزين شكل التطبيق لفتح أسرع — يعمل فقط على HTTPS حقيقي) |
| `manifest.json` | إعدادات PWA ("إضافة للشاشة الرئيسية") |
| `icon-180.png`, `icon-192.png` | أيقونات PWA |
| `sql-updates-run-in-supabase.sql` | تحديثات قاعدة بيانات تُشغَّل يدويًا مرة بـ Supabase SQL Editor (ليست جزءًا من الملفات المستضافة) |
| `api/mcp.js` | دالة Vercel خادمية (Node.js) لموصل الذكاء الاصطناعي — قراءة فقط، تحتاج متغيرَي بيئة `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY` بإعدادات المشروع على Vercel (لا تُحفظ بالكود إطلاقًا) |
| `package.json` | اعتماديات `api/mcp.js` فقط (`@modelcontextprotocol/sdk`, `@supabase/supabase-js`, `zod`) — الواجهة نفسها بلا أي اعتماديات npm |

### لماذا مقسَّم لـ 9 ملفات JS بهذا الترتيب تحديدًا؟

الملفات الرقمية (01 إلى 09) تُحمَّل **بنفس ترتيب أرقامها** بالضبط — هذا مهم لأن كل ملف قد يستخدم دوال/متغيرات مُعرَّفة بملف سابق له بنفس الترتيب (كلها بنفس النطاق العام "global scope"، تمامًا كما لو كانت لسا ملفًا واحدًا). **لا تُعِد ترتيبها ولا تحذف واحدًا بمعزل عن الباقي.**

## التشغيل محلياً

افتح `index.html` مباشرة بالمتصفح، أو قدّمه عبر أي خادم استضافة ثابت (static hosting) — المهم رفع كل الملفات والمجلدات أعلاه بنفس البنية.

## الاختبارات وفحص الصياغة

يحتاجان Node.js فقط (بدون أي تثبيت حزم إضافية):

```bash
npm test    # اختبارات وحدة على الدوال الصرفة (تشغّل الكود الفعلي من index.html داخل بيئة معزولة)
npm run check   # فحص صحة صياغة JavaScript بـ index.html و sw.js
```

يشتغلان تلقائيًا أيضًا عبر GitHub Actions على كل push و Pull Request (راجع `.github/workflows/ci.yml`).
